# context-surgeon

When your context is too large and your token budget is too small.

## Why This Exists

LLMs have context windows. Your documents don't care. You've got 50,000 tokens of meeting notes and a model that chokes at 8,000. What do you do?

Option A: Manually trim content, make bad decisions about what matters, lose important context. Option B: Let an algorithm make those decisions for you, systematically, using actual intelligence about what's important.

This is Option B.

context-surgeon analyzes your text, identifies redundancy and boilerplate, scores content by importance, and surgically removes what matters least until you fit your budget. It's not summarization (that changes your words). It's compression (that keeps your words, just fewer of them).

## Features

- Multiple compression strategies working together
- Redundancy detection via MinHash signatures (similar paragraphs get deduplicated)
- Boilerplate filtering (licenses, copyright notices, auto-generated markers)
- TF-IDF importance scoring (rare, meaningful terms beat common filler)
- Preserve head/tail options (keep your intro and conclusion intact)
- Multiple tokenizers (OpenAI tiktoken, Anthropic approximation, simple word-based)
- Model-aware budgeting (just say `--model gpt-4o --reserve 4000`)

## Installation

```bash
cargo install context-surgeon
```

Or build from source:

```bash
git clone https://github.com/sudokatie/context-surgeon
cd context-surgeon
cargo build --release
```

## Quick Start

```bash
# Compress to fit 8000 tokens
cat large_document.txt | context-surgeon --budget 8000

# Use model-based budgeting (reserve 4000 tokens for output)
context-surgeon --model gpt-4o --reserve 4000 document.txt

# Compress to 25% of original size
context-surgeon --budget 25% --stats document.txt

# Keep first and last 500 tokens no matter what
context-surgeon --budget 8000 --preserve-head 500 --preserve-tail 500 document.txt
```

## CLI Reference

```
context-surgeon [OPTIONS] [FILE]

Arguments:
  [FILE]  Input file (reads from stdin if not provided)

Options:
      --budget <TOKENS>        Target token budget (absolute or percentage like "25%")
      --model <MODEL>          Model name for context window calculation
      --reserve <TOKENS>       Tokens to reserve when using --model [default: 0]
      --preserve-head <N>      Always keep first N tokens [default: 0]
      --preserve-tail <N>      Always keep last N tokens [default: 0]
      --stats                  Print compression statistics to stderr
      --tokenizer <KIND>       Tokenizer: openai, anthropic, approximate [default: openai]
      --aggressive             Apply aggressive compression (may impact coherence)
      --conservative           Apply conservative compression (may not reach budget)
      --no-redundancy          Disable redundancy removal
      --no-boilerplate         Disable boilerplate filtering
      --no-extractive          Disable extractive compression
      --config <PATH>          Path to config file
  -h, --help                   Print help
  -V, --version                Print version
```

## Configuration

Create `~/.config/context-surgeon/config.toml`:

```toml
default_budget = 8000
tokenizer = "openai"

[thresholds]
redundancy_similarity = 0.85  # How similar paragraphs must be to dedupe (0.0-1.0)
importance_minimum = 0.30     # Minimum importance score to keep (0.0-1.0)
boilerplate_confidence = 0.90 # Confidence threshold for boilerplate detection (0.0-1.0)
position_decay = 0.95         # Weight decay for middle content (0.0-1.0)

[boilerplate_patterns]
custom_license = "(?i)^PROPRIETARY AND CONFIDENTIAL"
generated = "(?i)^// Generated by"

[preserve_patterns]
important_header = "(?i)^## Critical"
```

## How It Works

1. **Segmentation**: Text is split into paragraphs (the compression unit)
2. **Token counting**: Each segment gets an accurate token count via tiktoken
3. **Analysis phase**:
   - MinHash signatures computed for similarity detection
   - TF-IDF scores calculated for importance ranking
   - Boilerplate patterns matched against each segment
4. **Redundancy removal**: Similar segments are clustered; only the best representative kept
5. **Extractive compression**: Remaining segments ranked by importance, selected to fit budget
6. **Reassembly**: Selected segments joined in original order

The algorithm prioritizes:
- Segments near the start and end (context boundaries matter)
- Segments with rare, specific terminology (high TF-IDF)
- Segments that aren't redundant with others
- Segments that aren't boilerplate

## Performance

- Processes ~100KB of text in under 1 second
- Memory usage scales linearly with input size
- Parallel analysis using rayon for large documents
- OpenAI tokenizer is most accurate but slightly slower
- Approximate tokenizer is fastest for quick estimates
